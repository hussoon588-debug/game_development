# دليل تجهيز ونشر لعبة المدينة العقارية

## حالة الإصدار
هذه حزمة **مرشح نشر (Release Candidate)** وليست شهادة بأن التطبيق اجتاز اختبار إنتاج كامل. لم يمكن تثبيت الاعتماديات في بيئة العمل الحالية بسبب انقطاع/مهلة اتصال npm؛ لذلك يجب تشغيل خطوات الاختبار أدناه في بيئة لديها اتصال بمستودع npm وقاعدة PostgreSQL فعلية قبل فتح اللعبة للجمهور.

## المتطلبات
- Node.js 22 أو Docker مع Docker Compose.
- PostgreSQL 16+.
- OAuth Web Client من Google مع إعداد نطاق الإنتاج في Google Cloud Console.
- HTTPS على النطاق العام.

## تشغيل محلي عبر Node
1. انسخ `.env.example` إلى `.env` واضبط القيم الحقيقية.
2. لا تستخدم بيانات المثال كما هي، ولا تضع `.env` في Git.
3. ثبّت الاعتماديات: `npm install`.
4. جهّز قاعدة البيانات: `npm run db:migrate`.
5. نفّذ فحص الإعدادات: `npm run preflight`.
6. شغّل الفحوص: `npm run typecheck` ثم `npm run lint` ثم `npm run build`.
7. بعد نجاحها: `npm run start`.
8. افحص `/api/health`؛ يجب أن يعيد HTTP 200 و`{"ok":true,"status":"ready"}`.

## نشر Docker Compose
1. انسخ `.env.example` إلى `.env`.
2. أضف `POSTGRES_PASSWORD` إلى `.env` بقيمة عشوائية قوية باستخدام أحرف وأرقام و`-` و`_` فقط لتجنب مشاكل ترميز رابط PostgreSQL، واضبط `DATABASE_URL` عند تشغيل Node خارج Docker فقط. Compose يبني رابط قاعدة البيانات الداخلي تلقائياً من `POSTGRES_PASSWORD`.
3. اضبط `GOOGLE_CLIENT_ID` و`NEXT_PUBLIC_GOOGLE_CLIENT_ID` على OAuth Client ID نفسه، و`ADMIN_PASSWORD` على كلمة مرور عشوائية طويلة (16 حرفاً على الأقل).
4. شغّل `docker compose up --build -d`.
5. تحقق من `docker compose ps` وسجلّات `docker compose logs migrate app` ثم افتح `/api/health`.
6. المنفذ 3000 مربوط على `127.0.0.1` فقط؛ ضع Reverse Proxy أمام التطبيق وأنهِ TLS/HTTPS عليه؛ لا تعرض PostgreSQL إلى الإنترنت.

## إعداد Google OAuth
- أضف عنوان HTTPS الإنتاجي إلى Authorized JavaScript origins.
- لا تضف client secret إلى متغير يبدأ بـ `NEXT_PUBLIC_`.
- استخدم OAuth Web Client، وتأكد من أن النطاق وبيانات الاعتماد تطابق البيئة الفعلية.

## قبل إطلاق عام (إلزامي)
- تشغيل TypeScript وESLint وBuild بنجاح على نفس نسخة المشروع المراد نشرها.
- تجربة تسجيل Google حقيقي من نطاق الإنتاج وحسابات عادية وإدارية.
- تجربة إنشاء حساب، مكافأة الترحيب، شراء/بيع/إيجار عقار، تحويل، إيداع، سحب، إلغاء سحب، وإجراءات الإدارة.
- اختبار التزامن وإعادة إرسال نفس الطلب (idempotency) على PostgreSQL حقيقية.
- التحقق من النسخ الاحتياطي واستعادة نسخة احتياطية، ومراقبة الأخطاء، وحدود الاتصالات.
- إضافة rate limiting موزّع على تسجيل الدخول والتحويلات وواجهات الإدارة قبل فتحها للعامة.
- مراجعة قانونية وتشغيلية لأي رصيد/سحب ذي قيمة حقيقية. لا تفعّل مدفوعات حقيقية اعتماداً على هذا المشروع وحده.

## تنبيهات قاعدة البيانات
- `drizzle/0000_initial.sql` ينشئ جداول النسخة الجديدة بصورة idempotent. خذ نسخة احتياطية قبل تشغيله على قاعدة موجودة.
- الترحيل الأولي لا يضيف مفاتيح خارجية لأن مخطط التطبيق الحالي لا يعرّفها؛ إضافة القيود إلى قاعدة بيانات قديمة تحتاج خطة تنظيف للبيانات اليتيمة أولاً.
- لم يُنشأ `package-lock.json` لأن npm registry لم يكن متاحاً أثناء التجهيز. أنشئه وثبّت الاعتماديات في CI موثوق، ثم أضفه إلى الإصدار قبل اعتبار البناء قابلاً لإعادة الإنتاج.
- لا تضع `ALLOW_DEMO_SEED=true` في الإنتاج.
